# 03. 큐브(Cube)와 아이템 제작·개조 시스템 조사 보고서

대상: Steam 《TBH: Task Bar Hero》(app 3678970, 한국어 공식 표기 "TBH: 태스크바 히어로", 개발 Nugem Studio / Tesseract Studio, 정식 출시 2026-05-27).
조사 시점: 2026-11-21~22. 조사 시점의 최신 클라이언트는 **Ver 1.3.2 (2026-10-27 핫픽스)** 이다 [확인: 공식 Steam 공지].

[W]와 [F]는 서로 다른 운영자가 서로 다른 시점에 추출한 DB인데, 재료 효과 79종을 전수 비교한 결과 **공식 1.01.00 패치노트가 예고한 항목(저항 수치 상향, 일부 세공 재료 옵션 교체)만 달랐고 나머지는 완전히 일치**했다. 따라서 두 DB 모두 신뢰도가 높다고 판단한다.

주의: [W] 수치에 "v1.00.17"이라고 적힌 표는 **현재(1.3.2) 값이 아닐 수 있다.** 이후 패치에서 바뀐 것이 공식 확인된 항목은 해당 절에 따로 적었다.

참고로 "잠금(Lock)"은 큐브 기능이 아니라 인벤토리 기능이다(Alt+우클릭으로 아이템 잠금 → 자동 채우기/정렬 대상에서 제외) [확인: 공식 0.01.05, 1.2.5~1.3.0 노트].

## 2. 큐브 자체

### 2.1 해금·구조

- **큐브 해금 조건**: "영웅 레벨 4 무렵(시작 약 15분)"에 열린다는 서술이 taskbarhero.co 와 Mobalytics 가이드(검색 요약으로만 확인)에 있다 [추정 — 비공식, 정확한 조건식은 미확인]. 게임 데이터 추출 테이블에는 큐브 자체의 해금 조건 필드가 없다.
- **합성은 기본 해금**(`IsDefaultUnlocked=true`), 나머지 레시피는 큐브 레벨 도달 + 1회성 골드 지불로 해금한다 [확인: [W] `cube_recipes`, `cube_sub_recipes`].
- **슬롯**: 연금술 툴팁이 "아무 아이템 1~9개"이고 합성이 9개이므로 투입 슬롯은 9칸이다 [확인: 게임 문자열]. 플레이테스트 노트에 "큐브 중앙 슬롯의 레벨 텍스트"가 언급되어 결과물이 놓이는 중앙 슬롯이 따로 있다 [확인: 공식 0.01.04]. 정확한 UI 배치(3×3인지 등)는 [미확인].
- **자동 채우기(Auto Fill)** 가 있고, 1.3.0에서 합성에 '레벨 고정(Fixed Level)' 옵션이 추가됐다 [확인: 공식].
- 큐브 UI는 마지막으로 선택한 레시피를 기억한다(옵션으로 항상 합성에서 시작 가능) [확인: 공식 0.01.04].
- 큐브 레벨은 **교역선(스팀 마켓 연동) 사용 조건**이기도 하다: 큐브 Lv10 이상 [확인: 공식 1.00.07].

### 2.4 큐브 경험치 공식

[W]의 설명과 계산기 코드(사이트 번들 JS)에서 복원한 식이다. 등급·레벨·부위·종류 계수는 게임 테이블 값 그대로이고[확인], "레벨 근접도" 함수는 taskbarhero.wiki 가 "게임 코드에서 복원했다"고 밝힌 구현이다[추정 — 단일 출처].

```
EXP(아이템 1개) = floor( BaseCubeExp[등급] × LevelScale[아이템Lv] × GearTypeScale[부위] × ItemTypeScale[종류] )
                  × LevelMatch(큐브Lv, 아이템Lv) × (1 + 큐브 EXP 보너스%)
```
(테이블의 Scale 값은 1000 = ×1 로 저장되어 있다.)

**레벨 근접도 LevelMatch(c = 큐브Lv, t = 아이템Lv)** [추정 — taskbarhero.wiki 구현, "몬스터 처치 EXP와 같은 레벨 보정"이라고 설명]:

```
below = (t <= c)
r = below ? 2 : 5        # 감쇠 없는 구간 계수
i = below ? 5 : 6        # 완만 감쇠 구간 계수
a = below ? 0.5 : 0.4    # 완만 감쇠 구간 끝에서의 배율
o = ln(c + 1)
s = trunc((o/10 + 1) * r)      # |c - t| <= s 이면 1.0
k = trunc((o/10 + 1) * i)
d = |c - t|
if d <= s:            return 1
u = d - s - k
if u <= 0:            x = (d - s)/k ; return 1 - (1 - a)·x²
else:                 return a · (0.01/a)^( u / max(c/3, 3) )
```
예: 큐브 Lv20일 때 아이템 Lv1 0.08%, Lv5 0.8%, Lv10 15%, Lv15 88%, Lv20·25 100%, Lv30 80%, Lv35 13%, Lv40 0.8%, Lv45 0.05% (사이트 계산기 출력과 위 식이 일치함을 직접 검산했다). 즉 **큐브 레벨과 같거나 조금 높은 레벨의 아이템을 넣는 것이 가장 효율적**이고, 큐브보다 높은 쪽의 허용 폭이 더 넓다.

## 3. 합성 (Synthesis / 합성)

### 3.1 기본 규칙 [확인: 게임 문자열·공식 노트·[W]]

- 입력: **같은 등급**의 아이템 **9개**(`MaterialAmount = 9`, 533개 레시피 행 전부). 이름이 같을 필요는 없다.
- 분류(`ItemSynthesisType`)는 **Gear(무기·보조무기·방어구) / Accessory(장신구) / Material(재료)** 3종이고 한 번의 합성에 섞을 수 없다(장신구를 장비 합성에 넣을 수 있던 것은 0.01.05에서 버그로 수정). 1.3.0에서 **유물(Relic)·유물함(Reliquary)** 합성 레시피가 추가됐다(확률은 [미확인]).
- 출력: 그 분류의 결과 풀에서 **무작위 아이템 1개**. 결과 등급은 아래 가중치로, 결과 레벨은 3.3의 레시피 표로 정해진다. 활 9개를 넣어도 활이 나오는 것은 아니다.
- 골드 비용: 없음(`TriggerGoldCost = null`) [확인: [W] v1.00.17].
- 합성 불가 대상: 영혼석(0.01.04 수정), 기념 주화(`synthType = null`), 우주(Cosmic) 등급(상위 등급 없음), 1.00.07에서 삭제된 레벨(25·35·45·55·60·70·75·85)·"Type B" 장비(보유분은 사용 가능하나 합성·거래 불가), 잠긴 아이템.
- DLC 영웅(헌터·슬레이어)을 구매하지 않았으면 그 영웅의 장비는 결과로 나오지 않는다(1.00.12, 1.2.5에서 Lv50 누락분 수정).
- 마켓에서 산 아이템의 거래 불가 잔여 시간은 합성·제작 결과물에 승계된다(1.00.22).
- 합성도 소모한 9개만큼 큐브 EXP를 준다(연금술과 같은 계산, 골드만 없음) [추정 — [W] 해설].

### 4.2 골드 공식 [확인: [W] 테이블, [G]의 검산 예와 일치]

```
연금 골드 = BaseAlchemyGold[등급] × AlchemyGoldScale[아이템Lv] × GearTypeScale[부위] × ItemTypeScale[종류]
            × (1 + 큐브 연금 골드 보너스%)
```
- 등급 기본값·레벨 계수·부위 계수는 2.4절 표의 `BaseAlchemyGold`, `AlchemyGoldScale`, 부위 계수 열을 쓴다. 등급 기본값은 등급마다 약 3~3.5배씩 커진다(10 → 30 → 90 → 270 → 810 → 2,592 → 8,294 → 29,029 → 101,602 → 355,607).
- **큐브 EXP와 달리 레벨 근접도 보정이 없다** — 어떤 큐브 레벨에서든 제값을 받는다(단, 1.2.0의 +21레벨 제한은 적용) [추정 — [W] 해설·[G]].
- 재료 아이템은 `등급 기본값 × 12` (레벨·부위 계수 없음).
- 검산 예([G]): 초월 Lv80 오브 = 8,294 × 1,120 × 2 = 18,578,560골드(보너스 전). 표의 값(초월 8,294, Lv80 ×1,120, 오브 ×2)과 일치한다.

## 5. 제작 (Crafting / 제작)

### 5.1 규칙 [확인: 게임 문자열·[W]·[F]]

- 부위(주무기 / 보조무기 / 투구 / 갑옷 / 장갑 / 신발 / 장신구 7종)와 레벨 구간(단계)을 고르고 정해진 **제작 재료를 종류별로 1개씩** 넣으면 그 부위의 **무작위 장비 1개**가 나온다. 등급과 레벨은 확률로 정해지며 직업(검/활/지팡이…)·장신구 종류는 고를 수 없다.
- 레시피는 처음부터 고정이며 "레시피 획득(드롭·학습)" 개념은 없다. 큐브 레벨과 해금비로 단계가 열릴 뿐이다(2.2절). [W] `crafting_recipes` 는 8단계 × 7부위 = 56행, [F](1.3.0)는 9단계 × 7부위 = 63행.

- 결과물의 장식/세공/각인 슬롯 수는 결과 등급에 따른다(6.1절). 결과물의 고유 능력치 굴림 방식은 일반 드롭과 같은 아이템 정의를 쓴다 [추정].
- DLC 영웅(헌터·슬레이어) 장비는 해당 DLC 보유 시에만 주무기/보조무기 결과 풀에 추가된다(`EachDropOneWeight_DLCVariant`, 기본 4영웅 그룹 가중치의 1/4씩) [확인: [W] `drops`].
- 제작도 소모한 재료만큼 큐브 EXP를 준다 [추정 — [W] 해설].

## 6. 장식·세공·각인 (Decoration / Engraving / Inscription)

세 기능은 구조가 같다: **해당 슬롯이 빈 장비 1개 + 해당 재료 1개 → 능력치 1줄 부여**. 재료는 소모되고, 붙인 능력치는 "제거"(7절)로만 지울 수 있다(재료 미반환). 공식 1.2.0 노트의 설정 옵션("아이템 슬롯에 소켓을 항상 표시할지 선택")에서 보듯 이 슬롯들은 "소켓"이라고도 불린다.

- 영문 Engraving = 공식 한국어 **세공**, Inscription = **각인**이다. 한국어 커뮤니티/번역 사이트에서 Engraving을 "각인"으로 옮긴 자료가 있으니 주의.
- 골드 비용: 없음(`TriggerGoldCost = null`) [확인: [W] v1.00.17]. 성공 확률 개념 없음(항상 적용, 무엇이 붙는지만 무작위).
- 큐브 EXP는 주지 않는다 [추정 — [W] 해설].
- 재료 등급과 장비 등급/레벨 사이의 사용 제한(예: 고등급 재료를 저레벨 장비에 못 쓴다 등)은 데이터에서 찾지 못했다 [미확인].
- 잠긴 재료가 장식/세공/각인 재료로 쓰이던 문제는 1.3.0에서 수정 [확인: 공식].

### 6.2 수치 표기 규칙

아래 표의 수치는 DB의 내부값을 taskbarhero.wiki 의 표시 규칙으로 바꾼 것이다: 저항·고정 수치(공격력, 방어력, 최대 HP, 피해 흡수 등)는 내부값 그대로, 그 밖의 %류(속도, 치명타, 재사용 대기시간 감소, 막기·회피, 원소 피해 %, 체력 흡수 등)는 내부값 ÷ 10 = %. "공격력 +N%"처럼 %가 붙은 줄은 ADDITIVE(합연산 %) 수식, %가 없는 줄은 FLAT(고정값) 수식이다. 치명타 확률은 대부분 ADDITIVE(치명타 확률 "계수" %)이며, 0.01.03 플레이테스트에서 "치명타 기본값을 올리던 효과를 전부 % 증가 효과로 변경"했다 [확인: 공식]. 값은 범위 안에서 무작위로 굴려진다(굴림 단위 `Interval` 은 1 또는 10, 분포는 [미확인]).
"T숫자"는 능력치 단계(Tier 1~10)로 **제거 비용**(7절)을 결정한다. 단계 값은 [W] v1.00.17 기준이며, 1.3.0 표의 수치가 바뀐 항목도 단계는 같다고 보았다 [추정].

## 7. 제거 (Extraction / Removal / 제거)

- 기능: 장비에 장식/세공/각인으로 붙인 능력치 **1줄을 지우고 슬롯을 비운다**. 사용한 재료는 **반환되지 않는다**(게임 문자열: "장비에 부여된 능력치를 제거합니다. ※ 능력치 부여에 사용된 재료는 반환되지 않습니다.") [확인].
- 명칭: 데이터 enum 은 `EXTRACTION`, 공식 패치노트는 영문 "Remove/Removal", 한국어 "제거". 이름과 달리 **재료를 "추출"하는 기능이 아니다.**
- 해금: 큐브 Lv10, 1,000골드 [확인: [W]].
- 비용(골드): 지우려는 능력치의 **단계(T1~10)와 종류**로 정해지고 무기/방어구/장신구에 따른 차이는 없다(90행 전부 확인) [확인: [W] `extraction_costs` v1.00.17, taskbarhero.co 일치].

세공은 장식의 2배, 각인은 4배다. 따라서 **"옵션 다시 굴리기" = 제거(골드) + 새 재료 1개**가 원작의 유일한 재설정 경로이며, 비용이 시도 횟수에 따라 늘지는 않는다(장비 능력치 한정. 유물은 10절 조율).

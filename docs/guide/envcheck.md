# 환경 점검 애드온 사용법

`WIH_EnvCheck`는 본 게임이 아니라 **개발용 점검 도구**다. 와우 포에버 클라이언트에서만 확인할 수 있는 항목(API 존재 여부, 저장, 글꼴, 내장 아이콘, 모델 표시, 전투 중 창 조작, 계산 성능)을 한 번에 점검해 글로 보여 준다. 이 결과에 따라 본 애드온의 화면 구현 방식을 확정한다.

실제 게임 상태는 읽기만 하고 바꾸지 않는다. 캐릭터 이름, 서버 이름, GUID는 글자 모양만 남기고 가린다(예: `가가가`, `Aaaaaa-9999-9AAAAAA9`).

## 설치

1. `dist/WIH_EnvCheck-0.1.0.zip`의 압축을 푼다.
2. `WIH_EnvCheck` 폴더를 `World of Warcraft\_forever_\Interface\AddOns\` 아래에 넣는다. `...\AddOns\WIH_EnvCheck\WIH_EnvCheck.toc` 파일이 보이면 맞다.
3. 게임을 완전히 껐다가 켠다(새 파일은 `/reload`로 인식되지 않는다).
4. 캐릭터 선택 화면의 애드온 목록에서 "W.I.H 환경 점검"이 보이는지, 이름 뒤에 "(Camelot TOC)"가 붙어 있는지 확인한다.

애드온 목록에 아예 보이지 않으면 그 사실만 알려 주면 된다. TOC 인식 문제다.

## 점검 순서

채팅창에 먼저 입력해 오류 창을 켠다.

```
/console scriptErrors 1
```

1. `/wihcheck` 입력. 점검 창이 열리고 결과가 채워진다.
2. **모델 시험** 버튼을 누르고 2초 기다린다. 창 아래쪽 여덟 칸에 모델이 나타나는지 본다.
3. **동작 바꾸기** 버튼을 여러 번 누른다. 누를 때마다 모델의 동작(서 있기, 걷기, 공격, 시전, 죽음 등)이 바뀌는지 본다.
4. **모델 16개 부하** 버튼을 누르고 3초 기다린다.
5. 아무 몬스터와 잠깐 전투한다. 전투가 끝나면 **다시 점검**을 누른다.
6. `/reload` 입력 후 다시 `/wihcheck`.
7. 결과 글 상자를 누르고 `Ctrl+A`, `Ctrl+C`로 전체를 복사해 전달한다.

글이 너무 길어 붙여넣기 어려우면 `_forever_\WTF\Account\<계정 폴더>\SavedVariables\WIH_EnvCheck.lua` 파일을 전달해도 된다(게임을 끄거나 `/reload`한 뒤에 기록된다). 같은 내용이 들어 있다.

## 눈으로 확인해 알려 줄 것

| 항목 | 확인할 내용 |
|---|---|
| 애드온 목록의 이름 | "W.I.H 환경 점검"인지 "W.I.H 환경 점검 (Camelot TOC)"인지 |
| 한글 | 창의 한글이 네모(□)로 깨지지 않는지 |
| 창 | 제목 부분을 끌어 옮길 수 있는지, 글 상자를 마우스 휠로 스크롤할 수 있는지 |
| 텍스처 줄의 앞 세 칸 | "TGA 256", "TGA 300x200", "PNG 256"이 각각 대각선 줄무늬로 보이는지, 초록색 사각형이나 빈칸인지 |
| 텍스처 줄의 나머지 | 물음표, 검, 화염구, 전사, 기계공학, 라그나로스 아이콘이 보이는지 |
| 모델 칸 | 여덟 칸 중 어느 칸에 모델이 보이는지(칸 아래 이름으로) |
| 동작 | "동작 바꾸기"를 누를 때 동작이 실제로 달라지는지, 어떤 번호에서 공격·시전·죽음처럼 보이는지 |
| 오류 창 | 오류가 뜨면 그 글 전체 |
| 전투 중 | 전투 중에 화면에 "애드온이 차단되었습니다" 같은 알림이 떴는지 |

## 게임 밖에서 확인된 것과 아닌 것

- 게임 밖 Lua 5.1과 WoW API 대역 위에서 불러오기, 창 열기, 버튼 전부 누르기, 전투 진입·종료, 저장 왕복까지 실행해 Lua 오류가 없음을 확인했다(`lua5.1 Test/envcheck_load_test.lua`).
- 실제 클라이언트에서는 한 번도 실행하지 못했다. 이 도구가 첫 실행이다.
